# 状态卡与固定 dashboard

普通更新用精简卡片，完整计划固定在项目的 `.project-guide/dashboard.md`。二者来自同一份状态。工具生成的卡片可按用户语言压缩，必须保留事实和时间限制，不把“最后运行记录”改写为实时承诺。

## 精简卡

```text
项目：本轮交付名称 · 计划 v1 · 修订 r3 · 快照时间
本次交付：用户可观察的结果
当前范围已验证完成度：30%（按当前计划权重）
当前位置：已核验成果；当前主要未知
下一步：具体可执行动作
剩余执行时间：有依据的区间 / 暂无法可靠估计
需要你：一个核心问题 / 暂无，无需操作
完整计划与证据：固定总览入口
```

运行信息在开始/恢复、异常或用户关注时明确展示。固定文件总写“截至某时最后核验……；当前运行需刷新核验”。文件打开不会检查进程，也不会启动工作。生成新回复时 AI 先查宿主真实执行状态；查不到就说待核实。工具读取状态不是宿主运行检查。

## 阻塞卡

```text
停在哪里：缺失的具体条件
影响：哪部分暂停，其他哪些可继续
AI 已处理：查过什么、证据在哪里
需要你：提供信息 / 结果取舍 / 具体授权
在此期间：继续做什么；若无独立工作则明确等待和恢复入口
```

## 固定总览顺序

1. 目标、有限终点、版本、更新时间；已验证完成度、主要未知、剩余执行区间与等待。
2. 需要人参与的事项，区分仅知晓/补充/取舍/授权，重要事项不折叠。
3. 各部分交付、总/已验证权重、主支线、负责人、状态、依赖、下一步；显示部分与总体进度。
4. 依赖图；有足够时间依据时附资源受限的预计时间泳道；无依据不画精确甘特条。
5. 实际执行器最后核验、可继续工作、阻塞原因和解除条件。
6. 完成标准、成果与验证入口、对应版本和时间。
7. 范围、授权、最近变化、失败尝试和恢复入口。

图渲染不可用时依赖表完整保留。用“可并行”“实际可用执行槽位”和带时间的运行记录分别表达规划与事实。全部状态、计算和展示只对当前计划范围成立。

## 更新频率与降级

开始、恢复、验证通过、阻塞、实质变更和结束时保存；重要变化发卡片。频率沿用宿主进度通道，不给每个工具调用发卡。固定文件不自动后台刷新，无真实后台机制不承诺关聊天后继续。

不能保存时，在聊天显示“未持久保存/更新尚未保存”，附可复制交接：目标、计划、已验证成果、证据入口、决定、失败尝试、阻塞和下一步。不要把口头状态与旧文件说成已同步。没有安全互斥能力且无法保证单写者时，仅提供只读总览和独立报告。
