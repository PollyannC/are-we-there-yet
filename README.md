# Project Guide · 项目导航

让 AI 编程项目有清晰终点、可信进度和明确下一步。面向通过自然语言委托 AI 做网站或应用的人，尤其适合没有编程背景的使用者。

**当前版本：v0.1.0 试用版。** 先在一个交付终点明确的小任务中使用，再根据实际体验逐步改进。

## 它解决什么问题

项目做散、支线没有终点、换聊天后丢失上下文，以及 AI 不断要求你确认自己无法判断的工程选项。

五个核心要求：

| 要求 | 使用者得到什么 |
|---|---|
| 开始有约定 | 目标、交付物、完成标准、主支线边界 |
| 推进有依据 | 已验证成果、依赖、剩余工作和关键未知 |
| 停顿有去向 | 停在哪里、解除条件、可继续的独立工作 |
| 介入有理由 | 常规工程由 AI 判断，实质决定说明收益、代价、风险和建议 |
| 工作能接续 | 本地状态、证据、决策和交接记录 |

AI 会维护聊天状态卡及项目内固定的 `.project-guide/dashboard.md`。[查看虚构示例](examples/dashboard.md)。

## 安装

把下面这句话交给你使用的 AI 编程工具：

```text
请从 https://github.com/PollyannC/project-guide 安装项目导航 Skill。
技能目录是仓库中的 project-guide/，请安装整个文件夹，保留 scripts、references、agents 和 assets。
按当前工具支持的技能安装方式处理，安装后检查入口和附带工具是否可用。
```

私有仓库需要已有 GitHub 访问权限。也可从 [Releases](https://github.com/PollyannC/project-guide/releases) 下载 `project-guide-v0.1.0.zip`，解压后安装其中的 `project-guide/` 文件夹。

本版已在 Codex 本地环境试用；Codex 的技能调用名是 `$project-guide`。其他支持 `SKILL.md` 的工具可以读取同一入口，但宿主发现方式、权限和能力需要分别验证。没有文件能力时，协作规则可在聊天里使用，持久保存和自动计算会降级。

## 开始使用

在实际项目聊天中输入：

```text
使用 $project-guide 接手当前项目。先读取已有需求和成果，整理本轮交付终点、各部分交付和依赖，建立固定 dashboard，然后继续推进已授权工作。常规工程选择由你处理；需要我决定时，说明收益、代价、风险和你的建议。
```

梳理已有支线：

```text
使用 $project-guide 梳理这条支线。告诉我已经验证了什么、离接回主线还缺什么、做到什么程度就结束。请保存状态，并推进当前能做的工作。
```

换聊天继续：

```text
使用 $project-guide 恢复当前项目。先读取 .project-guide/project-state.json，核对真实成果、当前运行状态和协调者，再从下一项可执行工作继续。
```

若当前聊天尚未发现新安装的技能，可打开一个新的项目聊天，或直接提供已安装 `SKILL.md` 的路径。

## 进度怎样计算

- 完成度是当前计划中，通过验证且证据仍有效的末级里程碑权重比例。权重属于计划估计，不是精确工作量测量。
- 初稿、生成代码、开始运行或投入时间本身不计完成。成果文件变化会撤回对应完成资格，依赖它的资格也随之重新核验。
- 总范围无法可靠量化时，显示未知；有依据的剩余时间区间结合依赖和真实执行容量计算，等待另列。
- 固定 dashboard 是带时间与修订号的快照。AI 工作到关键节点时更新，打开文件不会启动任务或检查进程。
- 一个协调者更新总状态。其他执行者提交报告；代次、修订和文件锁用于防止过期覆盖。

## 本版范围

工具要求 Python 3.9+，仅使用标准库。互斥保存使用 POSIX `flock`，当前支持 macOS/Linux；缺少可靠互斥机制时仅允许只读状态检查。没有云端同步、后台调度、实时执行器适配器或第三方任务系统连接。

启用 Skill 不扩大既有权限，也不自动授权付费、发布、外发消息、额外 agents 或不可逆操作。它记录并帮助判断工作，不能替代真实验证或把自述完成当成证据。

仓库中的口语练习案例是虚构展示材料。真实项目状态、聊天记录、邮箱、凭证和运行数据不属于分发内容。

## 验证与后续改进

发布前已运行28项工具测试，并完成隔离任务试用和一次真实项目只读盘点。检查覆盖证据有效性、依赖、范围变更、工期、并发写入、接管、恢复和人类待办。真实项目盘点只证明能够按资料核对状态，不代表已验证普遍用户效果或所有宿主兼容性。

贡献者可在仓库根目录重跑：

```bash
python3 -B -m unittest discover -s project-guide/tests -v
```

后续优先根据实际使用修正信息层级、更新频率、估算依据和恢复体验。反馈时请描述任务目标、预期行为、实际行为及是否有可复现材料；移除个人资料、凭证和私有项目内容。
